方案 C 首版架构

协作能力优先，其次保证 runtime 可扩展、可恢复、可观测，画布编排后接入

从上到下的数据流
输入层

协作方案 / 未来画布 DSL

四种模式只是高层意图，先被编译成统一的执行计划，而不是直接各写一套运行逻辑。

↓
编排层

Plan Builders

Router / PlanExec / Supervision / PeerHandoff 各自生成 ExecutionPlan。

↓
运行层

Runtime + Step Executor

按统一 Step 模型执行：route / agent / parallel / review / handoff / finalize。

状态与恢复

Run State / Step State

持久化运行状态、步骤状态、失败原因和恢复命令。支持失败后重试、跳过、改派。

共享上下文

Artifact Store

结构化交接数据、阶段产物、最终结果统一沉淀，不再只靠自由文本串接。

执行适配

Harness Adapter

继续复用现有 RunAgentHarness、托管 Agent、工具链和工作区机制。

观测层

Trace / Event Log

把计划编译、步骤推进、产物写入、失败和恢复操作全部事件化。

↓
输出层

Run Console / Debug / Recovery UI

首版先支持失败后恢复；后续再让画布直接驱动 plan 与局部重跑。

这一版的关键边界

1

协作能力优先

先把并发、handoff、review、finalizer 做实。

2

Typed Runtime

先做强类型计划和步骤，不直接上完全自由 DAG。

3

失败后恢复

运行中保持自动；失败后支持重试、跳过、改派。

4

画布后接

首版先由方案编译 plan，之后再让 flowgraph/DSL 直接驱动。
